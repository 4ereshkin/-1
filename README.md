# Вариант 1 — инерциальная навигация при потере GPS

Qt Widgets / C++17. Исходное задание: `Контрольная работа 1 ПО ОНИ.pdf`, страницы 4–5.

## Запуск на этом компьютере

Windows / PowerShell, установленный Qt 6.12.0 и MinGW 13.1:

```powershell
cd D:\qt_pra\qt
$env:PATH = 'D:\Qt\Tools\mingw1310_64\bin;D:\Qt\Tools\Ninja;D:\Qt\6.12.0\mingw_64\bin;' + $env:PATH
& D:\Qt\Tools\CMake_64\bin\cmake.exe -S . -B build-windows -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=D:/Qt/6.12.0/mingw_64 -DCMAKE_CXX_COMPILER=D:/Qt/Tools/mingw1310_64/bin/g++.exe
& D:\Qt\Tools\CMake_64\bin\cmake.exe --build build-windows -j 2
& D:\Qt\Tools\CMake_64\bin\ctest.exe --test-dir build-windows --output-on-failure
& D:\Qt\6.12.0\mingw_64\bin\windeployqt.exe --release --no-translations .\build-windows\inertial_navigation.exe
.\build-windows\inertial_navigation.exe
```

Изменение PATH действует только в текущем сеансе PowerShell. После переноса проекта
на другой компьютер замените пути к Qt и инструментам. Можно также открыть
`CMakeLists.txt` в Qt Creator и выбрать установленный комплект Qt/MinGW.
`windeployqt` копирует библиотеки рядом с EXE: после этого его можно открыть
двойным щелчком. При переносе сохраните библиотеки и подпапки рядом с программой.

### Запуск на Linux

```bash
cd /home/home/QT
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release -j2
./run.sh
```

Исходная версия проверялась на Linux: GCC 13.3, Qt 5.15.13, CMake.
Creator для сборки и запуска не обязателен.

Редактирование формы: `designer src/mainwindow.ui`. Все виджеты и layouts
описаны в `.ui`, CMake AUTOUIC генерирует C++ интерфейс; вручную создавать
виджеты в коде не требуется. Если Qt Creator будет установлен, откройте
`CMakeLists.txt`, выберите Desktop kit и откройте `src/mainwindow.ui` в Design.

Версия с фильтром проверена на Windows с Qt 6.12.0 и MinGW: Release-сборка,
оба набора CTest и GUI-тесты с обычными окнами Windows. MSVC не проверялся.

## Управление

1. Введите ускорения X/Y в м/с² (−100…100, точка или запятая; по умолчанию 0.5/0.3).
2. **Старт** запускает QTimer с интервалом 50 мс. Синяя линия — оценка ИНС,
   зелёная — истинная траектория, оранжевая — оценка комплементарного фильтра.
   Маркеры показывают текущие позиции.
3. **Пауза / Продолжить** останавливает/возобновляет время модели. Ускорение
   можно изменить на паузе; позиции и скорости при продолжении сохраняются.
4. **Разовая коррекция ИНС** мгновенно совмещает синюю оценку позиции с истиной и обнуляет
   оценённую скорость, как явно указано в алгоритме задания. Ошибка сразу 0.
   Истинная скорость не меняется. После коррекции ошибка снова растёт;
   это упрощение задания. Оранжевая оценка фильтра этой кнопкой не изменяется.
5. **Сброс** останавливает таймер, удаляет траектории, обнуляет время и скорости,
   возвращает все три позиции в (300, 200). Введённые параметры и положения
   переключателей сохраняются; последовательность шума датчика начинается заново.

## Комплементарный фильтр и коррекция во время движения

Фильтр объединяет расчёт движения по ускорению с координатами условного внешнего
датчика (камеры или маяка). Датчик выдаёт новое измерение каждые 0.2 с, то есть
5 раз в секунду; прогноз движения рассчитывается каждые 0.05 с.

- **Автоматическая коррекция** включена по умолчанию. Её можно выключать и включать
  прямо во время движения или на паузе. Переключение не сбрасывает координаты,
  скорость, время и накопленные линии. При выключении оранжевая оценка продолжает
  двигаться по ИНС; при включении получает поправки по новым измерениям.
- **Внешний датчик доступен** позволяет имитировать потерю и восстановление
  измерений. Без них фильтр продолжает прогноз, но ошибка снова накапливается.
- **Шум датчика** — стандартное отклонение ошибки по каждой оси в метрах
  (0–10 м, по умолчанию 0.5 м). Это мера разброса случайных измерений;
  ноль задаёт идеальный датчик. Повторный запуск после сброса воспроизводит
  тот же шум в той же сборке, чтобы сравнивать настройки.
- **Время реакции** (0.2–20 с, по умолчанию 2 с) задаёт силу поправок.
  Меньшее значение ускоряет реакцию и усиливает влияние шума.
  Это параметр фильтра, а не гарантированное время полного устранения ошибки.

Все четыре настройки доступны во время движения. В статусе отдельно показаны
ошибка ИНС и ошибка фильтра. Для опыта выключите автокоррекцию на 20–30 с,
затем включите: оранжевая траектория постепенно возвращается к истинной.
При низком окне правая панель прокручивается. Формулы приведены в `docs/theory.md`.

## Иконка дрона и звук

SVG-иконка закреплена за истинной позицией, поворачивается по направлению истинной
скорости и сохраняет размер при масштабировании сцены. Коррекция оценок не двигает
дрон; сброс возвращает его в начальную точку.

Галочка **Звук полёта** включает приложенный MP3 на громкости 30%. Звук выключен
по умолчанию. Во время движения запись повторяется по кругу; пауза приостанавливает
её, продолжение возобновляет, сброс останавливает и перематывает к началу.
Полный цикл записи длится около 22.8 с. По окончании программа явно запускает
следующий цикл, если симуляция продолжает работать и галочка звука включена.
Галочку можно переключать на ходу. Ошибка аудиоустройства не останавливает симуляцию.

Файлы `assets/drone.svg` и `assets/drone-flight.mp3` скопированы из предоставленных
пользователем SVG и MP3. Они встроены в программу через `src/navigation_assets.qrc`,
поэтому при запуске исходные файлы из родительской папки не нужны.
Для сборки дополнительно используются модули Qt Svg и Multimedia; на Qt 6 также
SvgWidgets. Они уже установлены в используемом комплекте Qt.

Одна единица сцены соответствует метру; X вправо, Y вниз (координаты Qt).
В автообзоре камера охватывает все три полные траектории, в том числе при
отрицательном ускорении. Ручное управление описано ниже. Телепортация при коррекции не изображается как
реально пройденный отрезок. Время — модельное: один тик = 0.05 с, задержка ОС
не превращается в большой скачок интегрирования. История хранится до сброса;
приложение рассчитано на учебные сеансы, не на непрерывную многосуточную запись.

## Сетка и управление камерой

- Координатная сетка в метрах; шаг автоматически выбирается из ряда 1–2–5,
  чтобы подписи оставались читаемыми. Более тёмные линии — нулевые оси.
- **Колесо мыши** увеличивает/уменьшает масштаб около указателя.
- **Левая кнопка + перетаскивание** перемещает сцену. Также работают стрелки.
- **+ / −** меняют масштаб, когда фокус находится в области сцены.
- Ручное действие отключает автообзор; тики модели не сбрасывают масштаб/камеру.
- **F** (при фокусе в сцене) или галочка **«Автообзор траекторий»** снова включают
  автоматическое перемещение и масштабирование, чтобы все три траектории были видны.
- Возле движущихся точек находятся подписи «Истина» и «Оценка ИНС».
  Размер подписей не меняется при зуме.

## Движение по окружности

До старта выберите **«Движение по окружности»**. Задайте радиус (1…10000 м)
и период полного оборота (1…3600 с); по умолчанию 100 м и 40 с. Нажмите **Старт**.
Ускорения теперь не постоянные: они направлены к центру и меняются по синусу/
косинусу. Текущие компоненты показаны в строке `a` статуса.

Начальная точка (300, 200), центр (300−R, 200); начальная касательная скорость
равна 2πR/T. При Y вниз движение идёт по часовой стрелке. Идеальная траектория
замкнута, а оценка ИНС постепенно отходит от неё из-за смещения акселерометра.
Режим, радиус и период блокируются до **Сброса**, чтобы не телепортировать
траекторию при изменении параметров. Пауза и продолжение сохраняют фазу.
Разовая коррекция ИНС по-прежнему обнуляет скорость синей оценки согласно
исходному заданию: после неё эта оценка может существенно отклоняться от
окружности (см. теорию). Оранжевый фильтр продолжает работать независимо.

## Модули

- `src/simulation.*` — независимая от Qt модель, внешний датчик, комплементарный фильтр,
  интегрирование, разовая коррекция и сброс.
- `src/mainwindow.ui` — редактируемая форма Qt Designer с objectName из задания.
- `src/trajectoryview.*` — адаптивная сетка, камера и подписи точек.
- `src/mainwindow.*` — сигналы/слоты, валидация, QTimer, одна QGraphicsScene.
- `tests/test_simulation.cpp` — аналитические проверки модели и ошибок ввода.
- `tests/test_window.cpp` — кнопки, таймер, валидация, траектории и снимок окна.
- `docs/theory.md` — формулы, отличия от примера и ответы для защиты.

GUI-тесты используют платформу Qt `offscreen`; им не нужен доступ к рабочему
столу. Тест сохраняет `build/window-preview.png` после 60 секунд модельного
полёта. Обычный запуск приложения требует графического сеанса пользователя.

### Если запускать из терминала VS Code, установленного через Snap

В этой среде обнаружены унаследованные GTK-пути Snap, вызывающие
`libpthread.so.0: undefined symbol: __libc_pthread_init`. Это конфликт окружения,
не ошибка сборки. **Используйте `./run.sh` вместо прямого запуска бинарного файла.**
Скрипт очищает только переменные запуска текущего процесса, не меняя системные настройки.
Эквивалентная команда:

```bash
env -u GTK_PATH -u GTK_EXE_PREFIX -u GTK_IM_MODULE_FILE \
    -u GIO_MODULE_DIR -u GTK_MODULES \
    QT_QPA_PLATFORM=xcb ./build-release/inertial_navigation
```

С той же очисткой проверено открытие `designer src/mainwindow.ui`.
